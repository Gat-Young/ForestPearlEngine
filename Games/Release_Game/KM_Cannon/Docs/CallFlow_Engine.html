1. 한눈에 — 내가 채우는 곳 5가지

이 엔진은 "엔진이 부르고, 나는 채운다" 구조입니다. main도, 게임 루프도 엔진이 갖고 있고, 콘텐츠 제작자는 엔진이 정해진 시점에 부르는 함수 안을 채웁니다.

① GameProjectLoader.cpp 시작 1번

RegistProjectName() · LoadLevel() · LoadClassRegist() · LoadAssets() · ReturnStartLevel()
프로젝트 이름, 레벨 파일, 클래스 이름표, 에셋 목록, 시작 레벨.

② 레벨 JSON 데이터

Assets/Level/*.json — "gamemode" 이름과 "actors" 목록(class · name · transform). 여기 적힌 순서가 Initialize · BeginPlay · Tick 순서입니다.

③ GameMode FPAGameMode 상속

Initialize()에서 ControllerList.push_back("GameController") 후 __super::Initialize(). 컨트롤러를 만들어 주는 곳.

④ Controller FPAController 상속

Initialize()에서 키 매핑(AddMappingKey)과 함수 바인딩(BindMethod). 레벨 전체에 걸친 입력(F키 토글, 발사 등).

⑤ Actor · Pawn FPActor / FPPawn 상속

Initialize() 컴포넌트 만들기 → BeginPlay() 다른 액터 찾기 → Tick() 매 프레임 로직. 게임 내용의 대부분.

2. 엔진 전체 생명주기

Runners/Runner/Runner.cpp가 PreInitialize → Initialize → GameLoop → Finalize를 차례로 부릅니다. 노란 세로줄이 내 코드가 불리는 지점입니다.

상속 (is-a) 소유 (내가 만들어 가짐) 호출 돌려받는 값
  • ①에서는 액터가 아직 없습니다. 이 단계의 내 코드는 "이름표 등록 · 파일 목록 적기"만 합니다. 에셋은 LoadAssets()에서 등록만 하고, 엔진이 바로 뒤 AllAssetDataCreate()에서 한꺼번에 GPU 리소스를 만듭니다.
  • ②에서 생성 → Initialize → BeginPlay 가 "모든 액터에 대해 단계별로" 돕니다. 즉 모든 액터가 생성된 뒤에 Initialize가 시작되고, 모든 Initialize가 끝난 뒤에 BeginPlay가 시작됩니다.
  • GameMode · Controller가 항상 먼저입니다. 그래서 Pawn의 Initialize()에서 GetWorld()->GetController(0)로 컨트롤러를 가져와 입력을 바인딩할 수 있습니다 (Ship이 이렇게 함).
  • ④ 종료 시에는 소멸자만 불립니다. EndPlay 같은 함수는 없으므로 정리할 것이 있으면 소멸자에 둡니다.

3. 클래스 구조

3-1. 액터 계열 — 무엇을 상속해서 만드나

  • 레벨에 놓는 것은 전부 FPActor의 자식입니다. Initialize()와 BeginPlay()는 순수 가상이라 반드시 구현해야 합니다 (할 일이 없으면 빈 {}).
  • 입력을 받아 조종당하는 캐릭터·탈것은 FPPawn, 레벨 전체 입력은 FPAController, 컨트롤러 목록은 FPAGameMode를 상속합니다.
  • 컨트롤러는 레벨 JSON에 넣지 않습니다. GameMode가 ControllerList의 이름으로 만들어서 소유합니다 (액터 목록에도 없음).

3-2. 컴포넌트 계열 — 액터 안에 무엇을 붙이나

  • 모든 액터는 생성될 때 빈 FPSceneComponent를 루트로 갖습니다. Initialize()에서 메쉬 등을 만들고 SetRootComponent(Mesh)로 바꾸면, 레벨 JSON에서 받은 위치·회전·크기가 새 루트로 옮겨집니다.
  • FPStaticMeshComponent(this, "메쉬이름")은 만드는 순간 렌더 목록에 등록됩니다. 숨기려면 SetActive(false).
  • 루트가 아닌 컴포넌트는 SetupAttachment(RootComponent)로 루트 아래에 붙여야 위치가 계산됩니다 (Tick이 루트부터 자식으로 내려가며 계산하기 때문).

4. 매 프레임 안에서

FPGameInstance::Tick() → FPWorld::Tick() → 렌더링 순서입니다.

  • 입력 콜백은 액터 Tick보다 먼저 불립니다. 키 함수에서 값을 바꾸면 같은 프레임의 Tick에서 그 값을 쓸 수 있습니다.
  • Down = 누른 프레임 1번, Pressed = 누르고 있는 동안 매 프레임, Up = 뗀 프레임 1번.
  • 액터 Tick 순서 = 레벨 JSON 순서 (실행 중 Spawn한 액터는 맨 뒤). 다른 액터의 이번 프레임 결과에 기대는 코드는 순서를 확인하세요.
  • Tick()을 override하면 마지막에 __super::Tick()을 불러야 위치 행렬이 갱신됩니다. 빼먹으면 움직여도 화면이 안 바뀝니다.
  • 렌더러는 매 프레임 "활성 컴포넌트" 목록을 새로 만들어 그립니다. 그리는 코드를 직접 부를 필요는 없습니다.

6. 접근 치트시트 — 무엇을 어디서 가져오나

월드 · 시간

FPWorld* World = GetWorld();          // 액터 안
FPWorld* World = GetOwner()->GetWorld(); // 컴포넌트 안
float dt = GetWorld()->GetGameTimer()->DeltaTime(); // 초

다른 액터 찾기 FPGameplayStatics

FPActor* Ship = FPGameplayStatics::GetActorOfClass(GetWorld(), "Ship");
std::vector<FPActor*> List;
FPGameplayStatics::GetAllActorsOfClass(GetWorld(), "Cannon", List);
// "클래스이름" = Register 할 때 쓴 문자열. 이름은 actor->GetName()

입력 (Controller · Pawn)

// Controller::Initialize
GetInputComponent().AddMappingKey("IA_Fire", VK_RETURN, { ESwizzle::XYZ, ENegative::Positive });
GetInputComponent().BindMethod("IA_Fire", this, EKeyState::Down, &GameController::Fire);
// Pawn::Initialize — 컨트롤러는 이미 있음
FPAController* C = GetWorld()->GetController(0);
C->GetInputComponent().BindMethod("IA_Move", this, EKeyState::Pressed, &Ship::Move);
C->Possess(this);

위치 · 부착

SetActorLocation({ x, y, z });   // 월드, 회전은 도(°)
Mesh->SetRelativeLocation({...}); // 부모 기준
RootComponent->AddWorldOffset({...});
AttachToActor(Ship);             // 상대값 유지 → 부모 자리로 붙음
FTransform T = GetActorTransform(); // T.Location, T.QuaternionRotation

컴포넌트 · 보이기

Mesh = new FPStaticMeshComponent(this, "Canon_1_StaticMesh");
SetRootComponent(Mesh);
Light = new FPPointLightComponent(this);
Light->SetupAttachment(Mesh);
Mesh->SetActive(false);          // 숨기기 (삭제 API 없음)

에셋 · 머티리얼

// GameProjectLoader::LoadAssets 안에서만 등록
AssetLoader->LoadTexture("FX/FX_Smoke_dds.json", AssetOwner::User);
// 컴포넌트마다 다른 값이 필요하면 복제본
auto* AM = static_cast<FPAssetManager*>(FPGameInstance::Get().GetAssetManager());

실행 중 생성

FPActor* A = GetWorld()->SpawnActor("Cannon", "Cannon02");

클래스 등록 (이름표)

7. 흔한 실수

JSON에 등록 안 된 class 이름

레벨 JSON의 "class"가 Register에 없으면 OpenLevel에서 생성 결과가 nullptr인 채로 쓰여 시작하자마자 크래시합니다. 오타부터 확인.

Tick override에서 __super::Tick() 누락

위치를 바꿔도 화면이 그대로입니다. 월드 행렬은 루트 Tick에서 계산됩니다.

Initialize에서 다른 액터 사용

뒤 순서 액터는 컴포넌트가 아직 없습니다. 찾고 붙이는 일은 BeginPlay로.

SpawnActor의 이름 · 위치

Spawn한 액터는 Initialize · BeginPlay가 이름이 정해지기 전에 불립니다 (그 안에서 GetName()은 빈 문자열). 위치도 설정되지 않으니 Spawn 뒤에 직접 설정.

AttachToActor 하면 위치가 튐

부착은 상대값을 유지하므로 부모 자리로 붙습니다. 월드 위치를 지키려면 부착 전 GetActorTransform()을 저장했다가 부착 후 SetActorLocation/Rotation/Scale3D로 되돌립니다 (Cannon의 AttachKeepWorld).

GetMaterial().SetParameter가 다른 액터까지 바꿈

메쉬 에셋의 머티리얼은 공유입니다. 개별 값은 MakeMaterial + SetMaterial.

생성자 · 컴포넌트에서 GetWorld()

생성자에서는 Outer가 없고, 컴포넌트에는 Outer가 설정되지 않습니다. 액터는 Initialize부터, 컴포넌트는 GetOwner()->GetWorld().

에셋 경로 규칙

엔진은 Assets/<종류>/ 아래만 읽습니다 (Texture, Material, StaticMesh, Model, Shader …). JSON 안의 "Path"는 TextureResource/, Model/, ShaderResource/bin/ 기준입니다.

8. 따라하기 — 새 액터 하나 추가

  1. 클래스 — FPActor를 상속하고 세 함수를 채웁니다. 
    class Barrel : public FPActor
{
    FPStaticMeshComponent* Mesh = nullptr;
public:
    void Initialize() override
    {
        Mesh = new FPStaticMeshComponent(this, "Barrel_StaticMesh");
        SetRootComponent(Mesh);              // 레벨 JSON 위치가 Mesh 로 옮겨짐
    }
    void BeginPlay() override {}
    void Tick() override
    {
        float dt = GetWorld()->GetGameTimer()->DeltaTime();
        RootComponent->AddWorldRotation({ 0, 30 * dt, 0 });
        __super::Tick();                     // 꼭 마지막에
    }
};
  2. 에셋 — LoadAssets()에 텍스처 · 머티리얼 · 스태틱메쉬 JSON을 등록합니다. 머티리얼은 텍스처를, 메쉬는 머티리얼을 이름으로 참조하므로 기존 코드처럼 이 순서로 적는 것이 안전합니다.
  3. 이름표 — LoadClassRegist()에 Register<Barrel>("Barrel");
  4. 배치 — 레벨 JSON "actors"에 { "class": "Barrel", "name": "Barrel01", "transform": {...} }
  5. 빌드 · 실행 — 크래시하면 7장의 첫 번째(class 이름)부터 확인.
