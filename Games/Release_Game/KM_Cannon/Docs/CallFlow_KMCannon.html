KMCannon 모듈 호출 구조

대포 · 발사 FX를 KMCannon/ 폴더 하나로 묶었습니다. 다른 프로젝트는 창구 두 개(Loader, API)만 연결하면 되고, 모듈 안을 고치거나 늘려도 연결해 둔 줄은 다시 손댈 필요가 없습니다.

엔진 (ForestPearlEngine) 호스트 프로젝트 (KM_Cannon의 GameProjectLoader · GameController) 내 모듈 (KMCannon/) 데이터 (레벨 JSON · 에셋)

2. UML 다이어그램

색은 위 범례와 같습니다 (파랑 = 엔진, 노랑 = 호스트, 초록 = 내 모듈).

상속 (is-a) 소유 · 컴포지션 (내가 만들고 같이 사라짐) 참조 (포인터로 가리킴) 의존 · 호출 «call»

2-1. 클래스 다이어그램 — 누가 누구를 상속 · 소유 · 호출하나

  • 대포 · 소켓 · FX 세 클래스는 모두 엔진 FPActor를 상속합니다. 그래서 레벨 JSON의 "class" 이름만으로 엔진이 만들어 줍니다.
  • Cannon은 메쉬를 소유(◆, Initialize에서 new)하고, 소켓 · FX는 참조(→, BeginPlay에서 이름 · 클래스로 찾음)만 합니다. 소켓 · FX는 레벨에 따로 있는 액터라서입니다.
  • 호스트는 점선(«call»)으로 창구 두 개에만 의존합니다. 내부 클래스(Cannon 등)를 직접 include하는 호스트 코드는 없습니다.
  • CannonFireFX는 섬광 판 2장(FlashFront/Side)도 소유하지만, 그림이 복잡해져서 선은 생략했습니다.

2-2. 시퀀스 다이어그램 — Enter를 눌렀을 때

  • 실선 화살표 = 호출, 점선 화살표 = 돌려받는 값, 세로 막대 = 그 함수가 실행 중인 구간입니다.
  • ⑤ 소켓의 월드 트랜스폼은 이미 지난 Tick에서 부모(대포)를 따라 계산돼 있으므로, 쏠 때는 읽기만 합니다.
  • ⑦ 이후의 연기 이동 · 섬광 꺼짐은 이 호출 안이 아니라 매 프레임 CannonFireFX::Tick()에서 일어납니다 (4장 ⑤ 참고).

3. 연결 지점 — 호스트가 쓰는 줄은 딱 이것뿐

// GameProjectLoader.cpp
#include "KMCannon/Loader_KMCannon.h"

void LoadClassRegist()
{
    ...호스트 클래스 등록...
    Loader_KMCannon::RegisterClasses();   // Cannon · CannonSocket · CannonFireFX
}

void LoadAssets()
{
    Loader_KMCannon::LoadAssets();        // 대포 메쉬 + 발사 FX 에셋
    ...호스트 에셋...
}

// GameController.cpp
#include "KMCannon/API_KMCannon.h"

void GameController::FireCannon(FInputValue Value)
{
    API_KMCannon::FireAll(GetWorld());
}

이 세 줄이 연결의 전부입니다. 모듈 안에서 클래스를 하나 더 만들어 RegisterClasses()에 넣거나, 텍스처를 LoadAssets()에 넣어도 호스트는 그대로입니다.

6. 늘릴 때 — 어디만 고치나

밖에서 부를 기능 추가 (예: 이름으로 한 대만 쏘기)

// API_KMCannon.h — 선언 한 줄
bool Fire(FPWorld* World, const std::string& CannonName);

// API_KMCannon.cpp — 몸통
bool API_KMCannon::Fire(FPWorld* World, const std::string& CannonName)
{
    std::vector<FPActor*> Cannons;
    FPGameplayStatics::GetAllActorsOfClass(World, "Cannon", Cannons);
    for (FPActor* Actor : Cannons)
        if (Actor->GetName() == CannonName) { static_cast<Cannon*>(Actor)->Fire(); return true; }
    return false;
}

// 호스트 : 이미 API_KMCannon.h 를 include 했으니 바로
API_KMCannon::Fire(GetWorld(), "Cannon01");

새 클래스 · 에셋 추가

Loader_KMCannon.cpp의 RegisterClasses() / LoadAssets()에 한 줄씩 넣고, 새 .h/.cpp는 KMCannon/에 둡니다. 호스트의 GameProjectLoader.cpp는 그대로입니다.

7. 다른 프로젝트로 옮기는 체크리스트

  1. 코드 — KMCannon/ 폴더를 복사하고 .vcxproj에 8개 파일 추가 (필터 "KMCannon").
  2. 에셋 — 종류별 폴더 안의 KM/ 하위 폴더 8곳을 그대로 복사합니다. 이 프로젝트 전용 에셋은 섞여 있지 않습니다. 
    Assets/Shader/KM/            FXParticle VS·PS, BlenderCannonPixelShader (.json)
Assets/ShaderResource/KM/    위 셰이더 원본 (.psh / .vsh)
Assets/BlendState/KM/        BS_FX_ALPHA, BS_FX_ADD
Assets/Texture/KM/           FX/, Canon_T2/ (.json)
Assets/TextureResource/KM/   FX/, Canon_T2/ (이미지)
Assets/Material/KM/          FX/, Canon_T2/
Assets/StaticMesh/KM/        Canon_T2/Canon_1_StaticMesh.json
Assets/Model/KM/             Canon_T2/Canon_T2.fbx
    .vcxproj에는 셰이더 3개의 FxCompile 항목(Assets\ShaderResource\KM\…, 출력은 Assets\ShaderResource\bin\%(Filename))을 추가합니다. 컴파일 결과(.pso/.vso)는 빌드할 때 bin에 생기므로 복사하지 않아도 됩니다.
  3. 호스트 연결 3줄 — 3장의 RegisterClasses() · LoadAssets() · FireAll().
  4. 레벨 JSON — Cannon, CannonSocket(이름 = 대포이름 + _Muzzle), CannonFireFX 액터 3개를 그 프로젝트 레벨에 추가.

아직 남은 한계

  • 레벨 JSON의 액터 3개는 손으로 옮겨야 합니다. 엔진이 레벨 파일 하나만 읽기 때문이고, 모듈 안에서 SpawnActor로 만들 수는 있지만 그러면 총구 위치를 JSON으로 맞추는 장점이 사라집니다.
  • 배에 붙는 상대 위치 (2.8, 3.45, -8)는 Cannon.cpp에 고정입니다. 배가 없는 프로젝트에서는 레벨 JSON의 대포 위치가 그대로 쓰입니다.
  • 에셋은 KM/ 하위 폴더에 있어서 호스트 에셋과 폴더가 겹치지 않습니다. 단, 엔진은 에셋을 JSON 안의 "Name"으로 찾으므로 호스트에 같은 이름의 에셋(예: FX_Smoke_Material)이 있으면 충돌합니다.
